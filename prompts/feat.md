# icyPower

## 项目概述

icyPower 是一款聚焦于 **电池电量监测** 与 **充电提醒** 的轻量化工具，
通过两种互补的方式，帮助用户避免设备因电量耗尽而失效：

1. **手动充电跟踪**：对不便接入 HA 的设备（普通遥控器、玩具、门锁备用钥匙等），
   由用户在应用内登记并维护"上次充电时间"，系统按周期主动提醒。
2. **HA 设备监测**：对接 Home Assistant（HA），对所有由 HA 纳管的低功耗设备
   （传感器、门锁、IPC 摄像头、无线开关等）拉取实时电量，低于阈值即提醒。

- **目标用户**：拥有较多无线/电池供电智能家居设备，或家中存在多块需定期充电的
  设备的用户。
- **核心价值**：把"哪些设备快没电了 / 该充电了"从被动发现转为主动告知，
  避免因电量耗尽导致传感器离线、门锁失灵、遥控器失灵等可用性问题。
- **非目标**：不做电源管理、能耗统计、电池健康度分析；不做 HA 之外的设备接入；
  不做充电计划优化（仅做提醒与记录）。

## 具体功能

### 1. 电池电量监测、提醒

#### 1.1 基于时间周期的充电提醒（手动跟踪）

针对**未接入 HA** 的设备，由用户自行维护一份"充电周期设备清单"，
应用不感知设备真实电量，仅根据"上次充电时间 + 周期"倒推提醒时机。

**设备清单模型**

- 字段：设备名、分类（可选）、充电周期（天）、上次充电时间、备注（可选）。
- 用户在"设置 → 周期设备"中新增、编辑、删除条目。
- 设备名仅在本机使用，不与 HA 实体绑定。

**触发逻辑**

- 当 `now() − lastChargedAt ≥ cycleDays` 时，标记为 **待充电**，进入提醒。
- `lastChargedAt` 由用户在主页或详情页点击 **"已充电"** 按钮后重置为 `now()`。
- 用户也可在设置中手动编辑 `lastChargedAt`（用于补录忘记点击的情况）。

**提醒展示**

- 主页 Tab "周期设备"卡片顶部始终展示"距上次充电 N 天"。
- 超过周期后卡片置顶 + `warning` 色徽标（"已超期"）；超过 1.5 倍周期升级为
  `danger` 色徽标（"严重超期"）。
- 重置 `lastChargedAt` 后徽标消失，卡片回到正常排序。

#### 1.2 基于 HA 设备的电量提醒

针对**已接入 HA** 的设备，从 HA 读取实体电量，低于阈值时提醒。

**接入方式**

- 通过 HA 提供的实体（Entity）`battery` / `battery_level` 属性读取设备电量。
- 数据通过 HA WebSocket / REST API 实时/定时拉取（见 `ha.md`）。
- HA 中的房间/区域（Area）信息用于卡片分组与筛选。

**监控与阈值**

- 用户在"设置 → HA 设备"中选择要监控的设备，并独立配置每台设备的低电量阈值。
- 阈值默认 `warning = 20%`、`danger = 10%`，可逐设备覆盖。
- 任一被监控设备电量低于阈值即触发提醒。

**提醒展示**

- 主页 Tab "HA 设备"卡片显示当前电量百分比 + `warning` / `danger` 色徽标。
- 电量长期未更新（如 >24h 未上报）的设备标记为 `unavailable`，
  以次级提示呈现；是否推送系统通知由用户在设置中按需启用。

#### 1.3 提醒的通用行为

- 每次提醒支持用户 **确认 / 忽略**：
  - 确认：标记为已处理，从待办中移除。
  - 忽略：进入"已忽略"队列，可选设置静默时长，期间不再重复提醒。
- 确认/忽略操作对 **周期设备** 与 **HA 设备** 通用，但各自的"已处理"语义不同：
  - 周期设备：忽略 = 不再提醒直到下次 `lastChargedAt` 重置；
  - HA 设备：忽略 = 在静默时长内不再提醒，但电量持续下降仍可能触发更高级别。

### 2. 数据展示与分析

#### 2.1 实时仪表盘（主页）

主页通过 **居中 Tab** 切换两个独立视图，分别承载两种设备模型：

- **Tab A：周期设备**
  - 卡片字段：设备名、上次充电时间、距上次充电 N 天、**"已充电"按钮**、
    低电量徽标（超期/严重超期）。
  - 排序：超期置顶 → 按"距上次充电"倒序。
  - 点击"已充电"按钮即重置 `lastChargedAt`，无需进入详情页。

- **Tab B：HA 设备**
  - 卡片字段：设备名、当前电量百分比、所在房间、最近一次上报时间、低电量徽标。
  - 筛选器：房间、状态（正常 / 预警 / 危险 / 失联）。
  - 长按 / 右键卡片进入设备详情页。

#### 2.2 历史趋势

- 仅对 **HA 设备** 提供：单设备详情页展示最近 7 / 30 / 90 天的电量折线图。
- 周期设备无连续电量数据，不展示趋势图（其历史就是"已充电"事件的时间线）。
- 图表遵循 `ui.md` 的色彩 Token（`primary`、`warning`、`danger`）。
- 历史数据缺失时给出空态（Empty State）说明，而不是空白图。

#### 2.3 多设备对比（HA）

- 支持将多台 HA 设备加入同一"对比组"，在同一图表中叠加展示，
  辅助识别续航异常设备。
- 周期设备不参与对比。

### 3. 通知系统

#### 3.1 通知渠道

- **系统通知（System Notification）**：最优先，用于 `danger` 级别与超期超 1.5x 的
  周期设备提醒。
- **应用内通知中心（In-app Inbox）**：保留全部历史，便于回溯。
- 预留未来扩展渠道（HA Companion Push、邮件、Webhook 等），本期不实现。

#### 3.2 通知规则

- 每条规则至少包含：`触发条件`、`目标设备`、`静默策略`。
- 触发条件示例：
  - 周期设备：`超期` / `超期 ≥ N 天`。
  - HA 设备：`电量 < warning` / `电量 < danger` / `unavailable > N 小时`。
- 规则可启用/停用；多条规则同时触发时合并展示。

#### 3.3 静默时段（Quiet Hours）

- 用户可设置"勿扰"时间段（如夜间 23:00–07:00），期间不发送系统通知，
  但应用内通知中心仍正常记录，且 Tab 视图的徽标仍可见。

## 用户界面

### 1. 布局总览

- **主页**：顶部横栏 + 居中 Tab 切换区 + 横栏右上角设置入口。
  - 顶部横栏：左侧产品名 / 当前视图标题，右侧设置按钮。
  - 居中 Tab：**两个 Tab** —— "周期设备"、"HA 设备"。
- **设置页**：从主页进入；左侧导航 + 右侧表单的标准二级布局。
- **设备详情页**：仅对 HA 设备提供；周期设备无详情页，所有操作在卡片上完成。

### 2. 页面清单

| 路由                | 名称       | 关键内容                                                  |
| ------------------- | ---------- | --------------------------------------------------------- |
| `/`                 | 仪表盘     | Tab A 周期设备 + Tab B HA 设备，附筛选与徽标              |
| `/devices/ha/:id`   | HA 设备详情 | 当前状态、历史曲线、当前生效的提醒规则                    |
| `/inbox`            | 通知中心   | 时间倒序的全部通知，支持标记已读/忽略                     |
| `/settings`         | 设置首页   | 概览、HA 连接状态、数据管理                               |
| `/settings/cycle`   | 周期设备管理 | 周期设备清单的增/删/改（含 `lastChargedAt` 手动编辑）     |
| `/settings/ha`      | HA 设备管理 | 选择监控设备、配置每台阈值                                |
| `/settings/rules`   | 提醒规则   | 触发条件、目标设备、静默策略                              |
| `/settings/quiet`   | 静默时段   | 勿扰时间段                                                |
| `/settings/appearance` | 外观     | 主题模式：`light` / `dark` / `system`，实时预览并持久化   |

### 3. 状态设计

必须为以下场景提供明确视觉与文案：

- **空态（Empty）**：
  - 周期设备为空 → 引导去"设置 → 周期设备"添加。
  - HA 设备为空 → 引导检查 HA 连接 / 选择监控设备。
- **加载中（Loading）**：骨架屏（Skeleton），避免布局抖动。
- **错误（Error）**：HA 连接失败、数据拉取失败等，提供"重试"操作。
- **未授权（Unauthorized）**：HA Token 失效，引导用户重新认证。

### 4. 响应式与可访问性

- 最低支持宽度 360px（移动端）；卡片在窄屏自动堆叠。
- 键盘可达：Tab 顺序符合阅读顺序，焦点环（focus-visible）必须可见。
- 所有交互元素满足 WCAG 2.2 AA 对比度要求（参见 `ui.md`）。

### 5. 深色模式

#### 5.1 三种模式

应用必须支持三种主题模式：

| 模式     | 行为                                | 默认值 |
| -------- | ----------------------------------- | ------ |
| `light`  | 固定亮色                            |        |
| `dark`   | 固定暗色                            |        |
| `system` | 跟随操作系统的 `prefers-color-scheme` | ✅     |

> **默认行为**为 `system`：尊重用户在 OS 层做出的选择，绝大多数情况下不需要
> 在应用内手动切换主题。

#### 5.2 切换入口

- 设置 → 外观（新增路由 `/settings/appearance`）。
- 三个单选项 + 当前选中态实时预览（切换后立即生效，无需重启或刷新）。
- 选择结果 **立即持久化** 到本地（参见 §3 数据安全与隐私）。

#### 5.3 Token 来源（单一事实源）

- 所有暗色相关的颜色 / 阴影 / 边框 Token **必须** 由 `ui.md` 提供。
- 本文档不重复定义色值；约束为：
  - 实现层 **不得** 在组件内硬编码 `#xxxxxx`，必须通过 Token 引用。
  - 若 `ui.md` 暂未提供某 Token 的暗色取值，则视为 **规范缺口**——
    应在 PR 中先补齐 `ui.md`，再使用。
- 必备的暗色 Token 至少包括：
  - 表面：`surface` / `surface-elevated` / `surface-muted`
  - 文字：`text` / `text-muted` / `text-inverse`
  - 边框：`border` / `border-strong`
  - 语义（跨主题保持语义稳定，仅亮度调整）：`primary` / `secondary` /
    `success` / `warning` / `danger` 及其对应的弱化容器背景

#### 5.4 状态色的跨主题行为

- `warning` / `danger` / `success` / `primary` 等语义色在两种主题下 **含义不变**：
  低电量就是低电量，无论明暗。
- 但其"弱化背景"（如 `warning-soft` / `danger-soft`，用于徽标底色、Tint 区域）
  必须为暗色模式提供对应版本，避免在暗背景下出现刺眼的浅色大块面。

#### 5.5 图表与对比图

- 折线图、对比图的 **配色必须随主题切换**，不得简单把背景反色。
- 图表使用的颜色一律通过 Token 引用（如 `chart-series-1` ~ `chart-series-5`），
  暗色与亮色各定义一套；同一系列在两种主题下应保持 **可识别性**（即不会因为
  反色导致相邻系列混淆）。
- 网格线、坐标轴文字、Tooltip 背景在两种主题下都必须满足对比度要求。

#### 5.6 阴影与边框

- 暗色模式下 **降低阴影权重**（深色阴影在暗背景上几乎不可见，反而显脏）。
- 改用 **边框 + 微亮表面** 表达层次：`surface-elevated` 比 `surface` 略亮，
  `border` 用于分隔。
- 焦点环（focus-visible）在两种主题下都必须 **清晰可见**——禁止使用纯黑色或
  纯白色焦点环。

#### 5.7 持久化与首屏

- 用户的选择（含 `system`）持久化到本地；下次启动直接应用，避免闪烁。
- 首屏样式必须在 **JS / 框架主体加载前** 注入（`index.html` 内联 `<style>` 或
  同源脚本），确保不会出现"亮 → 暗"的 FOUC（Flash of Unstyled Content）。
- 当用户选择 `system` 时，本地存储的也是 `"system"` 字面量，而不是上一次解析后的
  实际值（`"dark"` / `"light"`）——这样 OS 切换主题时应用能即时跟随。

#### 5.8 系统主题变化的响应

- 运行时监听 `matchMedia('(prefers-color-scheme: dark)').change` 事件。
- 仅当用户选择 `system` 时响应此事件；选择 `light` / `dark` 时忽略，
  避免覆盖用户显式选择。

#### 5.9 可访问性

- 两种主题下所有正文文字与背景对比度 ≥ WCAG 2.2 AA（参见 `ui.md`）。
- 状态指示（低电量徽标、错误、危险）必须 **颜色 + 图标 + 文字** 三重冗余，
  避免色盲用户在暗色模式下仅靠颜色判断。
- 系统通知（System Notification）在两种主题下使用相同的语义色（系统通知的颜色
  由 OS 决定，应用层不强制覆盖）。

## 数据模型（两种设备）

| 维度       | 周期设备（Cycle Device）                | HA 设备（HA Device）                  |
| ---------- | --------------------------------------- | ------------------------------------- |
| 数据来源   | 用户手动录入                            | HA 实体（`battery` / `battery_level`）|
| 核心字段   | `name` / `cycleDays` / `lastChargedAt`  | `entityId` / `currentLevel` / `area`  |
| 触发条件   | `now − lastChargedAt ≥ cycleDays`       | `currentLevel < threshold`            |
| 重置方式   | 用户点击"已充电"按钮 → `lastChargedAt=now` | HA 自动推送新值                      |
| 卡片操作   | "已充电"按钮                            | 无（被动展示）                        |
| 历史数据   | 无趋势图，仅"已充电"事件时间线          | 7/30/90 天电量折线图                  |
| 详情页     | 无                                      | 有                                     |
| 对比视图   | 不参与                                  | 可参与                                |

## 其他要求

### 1. 软件架构

- **可拓展性**：业务按"领域"分层（周期设备、HA 设备、提醒、通知、设置、HA 接入），
  每一层通过清晰的接口（Interface / Port）暴露能力，新增渠道或新提醒策略
  时不应修改核心领域逻辑（参考 Clean Architecture / Hexagonal）。
- **可测试性**：核心领域纯函数化；与 HA 的 IO 通过适配层（Adapter）隔离，
  便于 Mock。
- **配置驱动**：周期设备清单、HA 监控设备、阈值、提醒规则等一律存储为声明式
  配置，避免硬编码到 UI 或业务逻辑中。

### 2. UI 风格

- 严格遵循 `ui.md` 中的 Ant 设计体系 Token：
  - 颜色仅使用 `primary / secondary / success / warning / danger / surface / text`。
  - 字号、间距严格使用 `ui.md` 给出的级差，禁止自定义魔法值。
  - 圆角、字体、字重遵循同一文件中的规定。
- **不要**为周期设备与 HA 设备分别引入不同色系；区分靠 **徽标 / 标签 / 排序位置**
  而非颜色，保证色板纯净。

### 3. 数据安全与隐私

- HA 访问令牌（Long-Lived Access Token）必须本地加密存储，不上传。
- 周期设备清单、已充电事件历史、应用内通知仅保存在本机，**不向外同步**。
- 设置页提供"清空所有本地数据"的入口（同时清空周期设备清单与 HA 监控配置）。

### 4. 性能

- HA 数据拉取采用增量更新 + 本地缓存，避免每次进入页面都全量请求。
- 主页两 Tab 首屏渲染 ≤2s（≥100 台设备场景下的参考值，具体以实现为准）。

### 5. 国际化

- 所有面向用户的文案通过资源文件（i18n）管理，默认中文，预留英文切换位。

### 6. 可访问性

- 参见 `ui.md` 中"无障碍"小节：WCAG 2.2 AA、键盘优先、可见焦点状态。
- 颜色仅作为辅助信息载体，关键状态必须同时有图标或文字标签。
- "已充电"按钮需提供等效的键盘触发与 ARIA 标签。

## 术语表

| 术语                | 含义                                                              |
| ------------------- | ----------------------------------------------------------------- |
| HA                  | Home Assistant，开源家庭自动化平台                                |
| Entity              | HA 中的设备抽象，本应用主要使用其 `battery` / `battery_level` 属性 |
| Cycle Device        | 由用户手动维护的周期充电设备，不接入 HA                           |
| HA Device           | 从 HA 实体读取电量的设备                                          |
| Threshold           | 低电量阈值；不同设备可独立配置                                    |
| Quiet Hours         | 静默时段，期间不发系统通知                                        |
| Inbox               | 应用内通知中心，所有触发的提醒均留痕                              |
